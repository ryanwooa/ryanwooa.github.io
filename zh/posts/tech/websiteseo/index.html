做 Web 应用时，功能跑通往往只占一半。另一半是：搜索引擎能不能找到你、能不能正确理解你的页面。这篇文章以 Next.js App Router 为例，结合一次真实项目的 SEO 改造，讲清楚「是什么、为什么、怎么配、上线后怎么管」。

什么是 SEO#

SEO（Search Engine Optimization，搜索引擎优化） 是一组技术和内容策略，目的是让网站在 Google、Bing 等搜索引擎的自然结果里更容易被找到、排名更合理。

搜索引擎的工作流程大致是：

  1. 爬取（Crawl）：爬虫访问你的 URL
  2. 索引（Index）：分析页面内容，存入索引库
  3. 排名（Rank）：用户搜索时，按相关性返回结果

SEO 不是「骗算法」，而是帮爬虫正确理解页面：标题是什么、摘要是什么、哪个 URL 是 canonical、哪些页面不该被索引。

对 Next.js 项目来说，SEO 主要落在：

  • HTML <head> 里的 meta 信息
  • 结构化数据（JSON-LD）
  • robots.txt / sitemap.xml
  • URL 结构、canonical、重定向
  • 非生产环境禁索引

为什么要做 SEO#

1. 自然流量是长期资产#

付费广告停投就断流；被正确索引的页面可以持续带来访问，边际成本很低。

2. 动态内容站尤其需要#

用户生成的路线、帖子、活动、个人主页等，每个详情页都是潜在入口。没有 generateMetadata、sitemap、结构化数据，爬虫往往只能看到同一个空壳 HTML。

3. 社交分享依赖同一套 meta#

微信、Twitter、Facebook、Pinterest 抓取链接预览时，读的也是 Open Graph / Twitter Card。SEO 和分享体验通常共用一套配置。

4. 避免「上线了但 Google 搜不到」#

常见原因：

  • staging 被索引
  • 登录墙挡住爬虫
  • 没有 sitemap
  • 重复 URL 没有 canonical

这些都可以在 Next.js 里系统性处理。

Next.js App Router 要配什么#

下面按层次说明，代码用通用写法，可直接套到自己的项目。

1. 环境区分：非生产环境禁止索引#

测试/staging 若被索引，会和正式站抢权重，甚至泄露未上线内容。

根布局里根据环境变量控制：

// app/layout.js
const isProd = process.env.NEXT_PUBLIC_BASE_URL === "https://www.example.com";

export const metadata = {
  title: {
    default: "My App",
    template: "%s - My App",
  },
  description: "应用描述",
  openGraph: {
    type: "website",
    siteName: "My App",
    title: "My App",
    description: "应用描述",
    images: [{ url: "/images/og-default.jpg", width: 1200, height: 630 }],
  },
  // 非生产环境：整站 noindex
  ...(!isProd && { robots: { index: false, follow: false } }),
};

robots.js 也可以双保险：非生产直接 disallow: /：

// app/robots.js
const BASE_URL = process.env.NEXT_PUBLIC_BASE_URL;
const isProd = BASE_URL === "https://www.example.com";

export default function robots() {
  if (!isProd) {
    return {
      rules: [{ userAgent: "*", disallow: "/" }],
    };
  }

  return {
    rules: [
      {
        userAgent: "*",
        allow: "/",
        disallow: [
          "/settings/",
          "/admin/",
          "/api/",
          // 登录后才能看的编辑页、消息页等
        ],
      },
    ],
    sitemap: `${BASE_URL}/sitemap.xml`,
  };
}

要点：公开页 allow，私有页 disallow，比全站放开再靠 noindex 更干净。

2. 全局 metadata + 页面级 generateMetadata#

App Router 推荐用 Metadata API，而不是手动改 <head>。

根布局：站点名、默认 title 模板、OG 默认图。

各页面：generateMetadata 动态生成。详情页从数据库读 title、description、封面图：

// lib/generateDetailMetadata.js
export async function generateDetailMetadata(id) {
  const item = await fetchItemById(id);
  if (!item) return {};

  const slug = toSlug(item.displayName);
  const canonical = `${BASE_URL}/items/${id}${slug ? `/${slug}` : ""}`;
  const coverImage = item.imageUrl ?? null;

  return {
    title: item.displayName,
    description: item.description ?? "",
    alternates: { canonical },
    openGraph: {
      url: canonical,
      title: item.displayName,
      description: item.description ?? "",
      images: coverImage ? [{ url: coverImage }] : [],
    },
    twitter: {
      card: "summary_large_image",
      title: item.displayName,
      description: item.description ?? "",
      images: coverImage ? [coverImage] : [],
    },
  };
}

页面里调用：

// app/items/[id]/[[...slug]]/page.js
export async function generateMetadata({ params }) {
  const { id } = await params;
  return generateDetailMetadata(id);
}

首页等静态页也可以单独写 generateMetadata，并设 canonical 指向根 URL。

3. 语义化 URL：ID + Slug#

纯 ID（/items/abc123）对 SEO 和可读性都一般。常见做法：

/items/{id}/{slug}

Slug 来自标题，SEO 友好；ID 仍是主键，改名只需改 slug。

缺 slug 时 301 到带 slug 的 URL，避免同一内容多个 URL：

export default async function ItemPage({ params }) {
  const { id, slug } = await params;
  const item = await fetchItemById(id);
  if (!item) notFound();

  if (!slug) {
    redirect(`/items/${id}/${toSlug(item.displayName)}`);
  }

  return <ItemDetail item={item} />;
}

每个详情页的 alternates.canonical 必须指向带 slug 的完整 URL。

4. 动态 Sitemap#

Next.js 13+ 支持 app/sitemap.js，构建或请求时生成 sitemap.xml。

静态页 + 数据库动态页：

// app/sitemap.js
export default async function sitemap() {
  if (!isProd) return [];

  const staticUrls = [
    { url: BASE_URL, changeFrequency: "daily", priority: 1 },
    { url: `${BASE_URL}/about`, changeFrequency: "monthly", priority: 0.5 },
    { url: `${BASE_URL}/search`, changeFrequency: "daily", priority: 0.8 },
  ];

  const dynamicUrls = [];
  const items = await fetchAllPublicItems();

  for (const item of items) {
    const slug = toSlug(item.displayName);
    dynamicUrls.push({
      url: `${BASE_URL}/items/${item._id}${slug ? `/${slug}` : ""}`,
      lastModified: item.updatedAt ?? new Date(),
      changeFrequency: "weekly",
      priority: 0.7,
    });
  }

  return [...staticUrls, ...dynamicUrls];
}

注意：

  • 只收录公开、应被索引的页面
  • 单类失败用 try/catch，避免整站 sitemap 挂掉
  • 非生产返回 []

5. 结构化数据（JSON-LD）#

Meta 告诉爬虫「标题和摘要」；JSON-LD 告诉爬虫「这是什么实体」。

按内容类型映射 Schema.org：

// lib/generateJsonLd.js
export function generateJsonLd(item) {
  const url = `${BASE_URL}/items/${item._id}/${toSlug(item.displayName)}`;

  const base = {
    "@context": "https://schema.org",
    name: item.displayName,
    description: item.description,
    url,
    ...(item.image && { image: item.image }),
  };

  switch (item.type) {
    case "attraction":
      return { ...base, "@type": "TouristAttraction" };
    case "trip":
      return {
        ...base,
        "@type": "TouristTrip",
        startDate: item.startDate,
        endDate: item.endDate,
      };
    case "article":
      return {
        ...base,
        "@type": "Article",
        datePublished: item.createdAt,
        dateModified: item.updatedAt,
      };
    default:
      return null;
  }
}

页面注入：

{
  jsonLd && (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}
    />
  );
}

上线后用 Google 富媒体结果测试 验证。

6. 按权限控制是否索引#

UGC 站不能把所有用户页都交给 Google。可按业务规则控制：

const isIndexable = item.permission === "public" && item.status === "approved";

return {
  title: item.displayName,
  description: item.description,
  alternates: { canonical },
  ...(!isIndexable && { robots: { index: false, follow: false } }),
};

private / draft / 未审核内容：不进 sitemap + 页面 noindex，比事后在 GSC 里删 URL 省事。

7. Middleware：别让登录墙挡住社交爬虫#

有 Auth0 等登录中间件时，Facebook、Pinterest 抓 OG 预览也可能被拦。

可对已知爬虫 UA 放行（仍走页面 SSR，只跳过登录校验）：

// middleware.ts
const isSocialBot =
  userAgent.includes("facebookexternalhit") ||
  userAgent.includes("Pinterestbot");

if (isSocialBot) {
  return NextResponse.next();
}

同时把 sitemap.xml、robots.txt 排除在 middleware 之外：

export const config = {
  matcher: [
    "/((?!_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)",
  ],
};

8. 其他 Next.js 相关项#

项目作用
manifest.jsonPWA / 移动端体验，间接影响体验信号
OG 默认图 1200×630分享无封面时的 fallback
viewport / themeColor移动端基础体验

Analytics（GA4、Meta Pixel 等）不直接等于 SEO，但 GSC 和 GA 对照看流量与索引很有用，建议一起配。

Google Search Console 配置#

代码配好后，用 GSC 告诉 Google「站点归你管」，并监控索引状态。

1. 添加资源#

  1. 打开 Google Search Console
  2. 添加资源，选 网域（Domain） 或 网址前缀（URL prefix）
    • 网域：验证 DNS，覆盖所有子域和协议
    • 网址前缀：验证单 URL 前缀，如 https://www.example.com

2. 所有权验证（常见三种）#

DNS TXT（网域验证，推荐）

在域名 DNS 加 Google 提供的 TXT 记录，一次验证整域。

HTML 文件

把 googleXXXX.html 放到 public/，部署后访问 https://www.example.com/googleXXXX.html。

HTML meta 标签

// app/layout.js
export const metadata = {
  verification: {
    google: "your-verification-code",
  },
};

Next.js Metadata API 原生支持，不用手写 <meta>。

3. 提交 Sitemap#

验证通过后：索引 → Sitemap → 添加 https://www.example.com/sitemap.xml。

几天内看「已发现 / 已编入索引」数量，确认动态页是否被收录。

4. 日常要看什么#

  • 网页 → 索引：已索引、Excluded、Error 各多少
  • 体验 → Core Web Vitals：LCP、CLS 等
  • 链接：外链与内链概况
  • 网址检查：单 URL 是否可索引、canonical 是否被采纳

新站或大量新 URL 时，用「网址检查 → 请求编入索引」加快首屏收录（不必每个 URL 都手点）。

5. 其他平台（可选）#

  • Bing Webmaster Tools：可导入 GSC 数据
  • Pinterest / 其他：有时需 public/ 下验证 HTML 或 meta，与 GSC 类似

复盘：还值得补的几件事#

1. 先画「索引边界」#

先定哪些该被搜到：公开详情、列表、关于页；哪些不该：设置、后台、编辑、私信。

对应到 robots.js、sitemap.js、页面 robots meta 三处，避免遗漏。

2. Canonical 是一等公民#

带 query、不带 slug、旧路径跳转，都要指向唯一 canonical，否则 GSC 会出现「重复网页、Google 选择了不同的 canonical」。

3. 环境变量是 SEO 开关#

用 NEXT_PUBLIC_BASE_URL 区分生产/测试，比 NODE_ENV 更稳——有些 staging 也是 production build。

4. Sitemap 是「建议」，不是保证#

页面还要满足：可爬、有内容、未被 noindex、加载正常。Meta + JSON-LD + canonical 仍缺一不可。

5. 社交预览要单独测#

Facebook Sharing Debugger、Twitter Card Validator 各测一遍，确认 OG 图和描述正确。

6. 性能也是 SEO 因素#

Core Web Vitals 影响排名。Next.js 侧：next/image、字体优化、避免详情页不必要的大客户端 bundle。

7. 国际化（若有多语言）#

用 alternates.languages 声明 hreflang，避免多语言 duplicate content。

最小 Checklist#

上线前可逐项勾：

  • 生产环境根 layout 未误开 noindex
  • staging / preview 已 noindex + robots disallow
  • robots.txt 放行公开页，屏蔽私有路径
  • sitemap.xml 含静态页 + 应索引的动态页
  • 详情页有独立 title / description / canonical
  • OG + Twitter Card 配齐，有默认 fallback 图
  • 重要内容类型有 JSON-LD
  • URL 带 slug，缺 slug 会 301
  • 私有内容 noindex 且不进 sitemap
  • Middleware 不挡 sitemap / robots / 社交爬虫
  • GSC 已验证并提交 sitemap
  • 富媒体结果测试、社交分享调试通过

结语#

Next.js 做 SEO 的核心就一句话：让爬虫在服务端 HTML 里看到和用户一致的、结构清晰的页面信息。

App Router  metadata、generateMetadata、sitemap.js、robots.js 已经把大部分工作标准化了。真正拉开差距的是业务细节：哪些页该索引、canonical 怎么定、动态数据怎么进 sitemap、登录体系怎么不影响爬虫。

把边界画清楚，再按 checklist 落地，比堆关键词有用得多。
