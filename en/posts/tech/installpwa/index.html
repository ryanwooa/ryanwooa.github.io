Background#

Some time ago, my boss told me that our web project needed to support offline usage — allowing users to use certain features even when they’re not connected to the internet. At first, I thought this was kind of magical. Normally, when a webpage can’t connect to the server, it just shows a 404 error, right?

After looking it up online, I learned about something called Service Worker, which can cache webpages so that when offline, the previously cached pages can still be used. At the same time, this technology also allows a website to work like an app: users can add the site to their phone’s home screen and open it just like an app. This is called PWA.

PWA#

PWA (Progressive Web App) is a technology that enables a website to feel like a native app.

In essence, it’s an “upgraded version of a website” that gives your site the following capabilities:

  • Can be installed on the phone’s home screen and opened like an app

  • Supports offline access (usable even without internet for some features)

  • Supports push notifications

  • Starts quickly and offers an experience close to native apps

  • Supports full-screen, splash screen, icons, and more

The core technology behind PWA is the Service Worker:

  • A Service Worker is a background JavaScript script in the browser that can intercept network requests from the webpage.

  • It can cache static resources (HTML, JS, CSS, images, etc.) locally.

  • When the user is offline, the Service Worker responds with cached content, enabling offline access.

Advantages of PWA:

  • Cross-platform: One codebase works on PC, Android, and iOS — no need to write separate native apps for each platform.

  • No app store required: users can access directly through the browser.

  • Auto-updating: Every time a new version is deployed, users get it automatically on their next visit.

How to use it#

My website is built with Next.js, so I checked the Next.js documentation and searched npm to see what packages were available. For Next.js, there’s a package called serwist/next, one of the earlier ones supporting PWA. There are also forks like @ducanh2912/next-pwa ，next-pwa . I decided to use @ducanh2912/next-pwa .

After installing the package, you only need to configure a few required files to get it working. I won’t go into the installation details here, but I’ll highlight a few important things.

The most important file is the manifest file, which works like an app’s app.json. It defines the app name, description, sizes, theme colors, display mode, and more.

Here’s an example:

{
  "name": "PWA App",
  "short_name": "App",
  "icons": [
    {
      "src": "/icons/android-chrome-192x192.png",
      "sizes": "192x192",
      "type": "image/png",
      "purpose": "any maskable"
    },
    {
      "src": "/icons/android-chrome-384x384.png",
      "sizes": "384x384",
      "type": "image/png"
    },
    {
      "src": "/icons/icon-512x512.png",
      "sizes": "512x512",
      "type": "image/png"
    }
  ],
  "theme_color": "#FFFFFF",
  "background_color": "#FFFFFF",
  "start_url": "/",
  "display": "standalone",
  "orientation": "portrait"
}

The second one is to add metadata in app/layout.tsx or pages/_app.tsx. Here’s an example.

import type { Metadata, Viewport } from "next";

const APP_NAME = "PWA App";
const APP_DEFAULT_TITLE = "My Awesome PWA App";
const APP_TITLE_TEMPLATE = "%s - PWA App";
const APP_DESCRIPTION = "Best PWA app in the world!";

export const metadata: Metadata = {
  applicationName: APP_NAME,
  title: {
    default: APP_DEFAULT_TITLE,
    template: APP_TITLE_TEMPLATE,
  },
  description: APP_DESCRIPTION,
  manifest: "/manifest.json",
  appleWebApp: {
    capable: true,
    statusBarStyle: "default",
    title: APP_DEFAULT_TITLE,
    // startUpImage: [],
  },
  formatDetection: {
    telephone: false,
  },
  openGraph: {
    type: "website",
    siteName: APP_NAME,
    title: {
      default: APP_DEFAULT_TITLE,
      template: APP_TITLE_TEMPLATE,
    },
    description: APP_DESCRIPTION,
  },
  twitter: {
    card: "summary",
    title: {
      default: APP_DEFAULT_TITLE,
      template: APP_TITLE_TEMPLATE,
    },
    description: APP_DESCRIPTION,
  },
};

export const viewport: Viewport = {
  themeColor: "#FFFFFF",
};

You can also set some other things here, for example making the iPhone status bar transparent so that content can be displayed inside the status bar.

Offline functionality#

To enable offline use, you need to configure Runtime caching. next-pwa comes with some custom caching configurations, but you can configure it as you like. For example, I’ve included the web pages that I want cached, and also the addresses of some image servers. This way, when users are offline, they can still see the images that were cached earlier while they were online.

const withPWA = require("@ducanh2912/next-pwa").default({
  // Your other options,
  extendDefaultRuntimeCaching: true,
  workboxOptions: {
    runtimeCaching: [
      // Your runtimeCaching array
    ],
  },
});

module.exports = withPWA({
  // Your Next.js config
});

Add Website to Home Screen#

  • For iPhone, just open the page in Safari, then select “Add to Home Screen” from the menu.
  • For Android devices, after selecting “Add to Home Screen”, there are two options: one is Install, and the other is Add Bookmark. To get an app-like experience, you should choose Install. This way, the website can be accessed on the phone just like a native app.

Conclusion#

Overall, PWA really impressed me. After configuring it, I could use the website on my iPhone just like an app — without seeing the browser’s UI, the website itself takes up the entire screen. By adjusting the website’s responsive design and other settings, it’s fully possible to deliver an app-like experience while reducing development costs.
